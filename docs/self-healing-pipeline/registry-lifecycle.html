The Classifier Registry: Lifecycle and Loop Closure

A human-curated catalog of Ariadne's known failure modes. Triage reads it to suppress already-explained false positives; its permanent slice bundles into @ariadnejs/core; and every status transition is a human decision — proposed by the reconcile-registry skill and written through one fenced script — making the registry the surface where the loop actually closes.

What the registry is

The registry lives at .claude/skills/triage/known_issues/registry.json and is typed by KnownIssue in packages/types/src/known_issues.ts. On disk it is a versioned envelope — { schema_version: 1, rules: KnownIssue[] } — parsed by parse_known_issues_registry_json(), which rejects any schema_version mismatch outright. Each row catalogs one failure mode of the call-graph engine: a builder-chain dispatch the resolver cannot follow, a constructor call the tree-sitter query misses, a dynamic property-keyed callback that is unresolvable in principle.

One writer. Neither pipeline skill writes the registry. triage reads it as a filter; plan neither reads nor writes it (its dedup signal is backlog frontmatter). The human is the registry's sole decider, and every edit goes through atomic_update_registry. The deliberate decision step is the reconcile-registry skill over one fenced writer, reconcile_registry.ts — the registry's analogue of prioritize over export_to_backlog.ts. The lock, the rename-atomic write, and the AST-level write-boundary test that enforces this are covered on Write Boundaries.

Match mechanism vs user-facing label

Each rule carries two distinct concerns, deliberately decoupled:

classifier.kind — how a rule matches

  • none — a cataloged failure mode with no automated classifier yet. Documents and counts; never auto-classifies.
  • predicate — a hand-authored expression over a closed, serializable DSL (all/any/not combinators over leaves like diagnosis_eq, decorator_matches, syntactic_feature_eq). No eval; schema validation rejects unknown operators. Carries an axis and a min_confidence.
  • builtin — a TypeScript function generated into auto_classify/builtins/check_<group_id>.ts and dispatched by function_name through the generated barrel.

classification — what a match reports

The public label surfaced through EntryPointClassification to library consumers via Project.get_classified_entry_points(). One of:

  • framework_invoked (with a framework name)
  • dunder_protocol
  • test_only
  • indirect_only

Permanent rules carry it; wip rules may omit it, defaulting to framework_invoked keyed by the rule's group_id. Keeping label separate from mechanism lets a single classifier kind drive different public labels.

Lifecycle: every arrow is a human edit

State by state

StateMeaningWho flips it, and on what evidence
wip A cataloged failure mode under active observation. Born with classifier.kind: none; gains a predicate or builtin classifier when the human authors one. Once classified, triage's filter suppresses the matching false-positive class on the next run. The human authors the row, grounded in plan's proposals — novel:* groups that crossed the promotion threshold.
permanent A resolver limitation that holds in principle (e.g. a computed property key can never be statically linked). The rule graduates out of the skill and into the library: its row joins the bundled core slice. The human, after promotion review, names the rule with reconcile-registry --id <group_id> --promote; the flip regenerates packages/core/src/classify_entry_points/permanent_data.ts via generate_permanent_data.ts, and permanent_data.sync.test.ts guards the slice against drift thereafter.
fixed The underlying Ariadne defect is repaired; the rule is retired from active filtering but kept as the audit record. The human, once a fix-bearing (fix/feat) Conventional-Commits scope in this repo's git log matches the rule's backlog_task by exact id — the match reconcile-registry detects. The schema records no commit hash — the backlog_task link plus the git log are the audit trail.

Drift detection

A classifier can rot: its predicate stays valid but grows too narrow for the failure mode it covers, so entries it should explain leak through to investigation. When a triage-investigator returns an fp-classifier-regression verdict against a rule, finalize rolls it into the published run's classifier_regressions[] aggregate. The human reads that slice and records it on the rule:

  • drift_detected: true — the flag that marks the rule for re-investigation at promotion review.
  • drift_evidence[] — one { entry_index, evidence_excerpt } row per flagging verdict, append-only across runs, so the promotion reviewer sees every flag that recommended re-investigation.

The reconcile-registry skill reads the published classifier_regressions[], proposes drift_detected: true plus the append-only, entry_index-deduped drift_evidence[] rows, and the human confirms. Drift is a review signal, not an automated transition: a drift-flagged rule stays wip until the human widens (or splits) its classifier.

The permanent slice: how core consumes the registry without the skill

The full registry — wip rows included — stays in the skill tree. @ariadnejs/core ships only the permanent slice, as plain TypeScript:

  1. Regenerate. The human-driven promotion (reconcile-registry --id <group_id> --promote) flips a row to permanent and runs generate_permanent_data.ts, which renders classify_entry_points/permanent_data.ts from the source registry through the shared render_permanent_slice_module in /types. The module exports PERMANENT_REGISTRY_FILE — the same { schema_version, rules } envelope, with the schema_version copied verbatim from the source. permanent_data.sync.test.ts asserts the committed slice byte-equals a fresh render thereafter.
  2. Build. Because the slice is a .ts module, tsc emits it into dist/ as part of the normal build — no copy step. registry_permanent.ts re-exports it as PERMANENT_REGISTRY plus PERMANENT_REGISTRY_SCHEMA_VERSION.
  3. Load. load_permanent_registry() in registry_loader.ts validates the slice on first call, then returns a cached, structurally-cloned copy with every regex-bearing predicate leaf pre-compiled (compiled_pattern: new RegExp(...)). The clone is a typed pure function — no JSON round-trip — so non-serializable fields can never be silently dropped, and callers share no mutable substructure with the module constant.

Fail-loud validation

validate_permanent_slice() throws PermanentRegistryError rather than silently degrading classification, on any of:

CheckWhy it fails loud
Slice schema_version ≠ KNOWN_ISSUES_REGISTRY_SCHEMA_VERSION from @ariadnejs/typesThe bundled slice is stale relative to the types package — it must be regenerated from the source registry.
Any rule with status !== "permanent"The slice generator's status filter regressed; a wip rule in the library would classify with unreviewed logic.
Any rule with classifier.kind === "none"An unclassified rule cannot match anything; its presence means the slice must drop it, and shipping it signals a regeneration regression that would mis-classify for the next library user.

The predicate-cloning switch is exhaustiveness-forced: adding a new PredicateOperator to the DSL produces a compile error in the loader until its author decides whether the new operator carries a regex.

When a fixed row resurfaces

A fixed row can come back: the same member_symbol reappears in a later run's published triage_results. Identity here is the stable (file_path, name, kind, start_line) tuple — not the positional novel-<entry_index> id, which shifts run to run. The resurfacing is surfaced for human review; there is no automatic re-flip back to wip.

Why no auto-reflip. The registry stays auditable precisely because every transition has a single accountable author. A resurfaced symbol may mean the fix regressed — or that a different defect now produces the same false positive and deserves its own rule. Only a human can tell those apart, so the system reports the resurfacing and waits.

How this closes the loop

  • Registry → triage: a wip or permanent rule authored from this run's findings suppresses that false-positive class on the next run's filter — the heal takes effect one run later.
  • Registry → library: the permanent slice carries reviewed, in-principle limitations into @ariadnejs/core, so every consumer of Project.get_classified_entry_points() benefits without running the skill.
  • Registry → audit: backlog_task plus the target repo's git log tie each fixed flip to the commit that earned it, with no stored hash to go stale.
