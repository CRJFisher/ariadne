The Self-Healing Pipeline

Every false positive in Ariadne's entry-point detection is an Ariadne defect. This pipeline senses those defects (triage), classifies them into engineering work (plan), lets a human actuate the fix — and re-reads what it learned on the next run, so the same false positive never recurs.

sense — triage classify — plan actuate — human loop closure — durable stores

Architecture at a glance

How it all fits together

Ariadne's core job is to detect call graphs and find a codebase's entry points. Doing that well means correctly distinguishing genuinely-unreachable code from code whose callers the resolver failed to connect — and every such failure is a defect in Ariadne itself. The pipeline is the operational loop around the engine: it surfaces those defects, turns them into actionable engineering work, fences the actuation behind a human, and re-reads what it learned on the next run.

Sense — triage

Triage runs as a self-contained per-commit job. It calls @ariadnejs/core to detect entry-point candidates, then partitions every candidate into three buckets: entries an existing classifier rule already explains (auto-classified, never investigated), entries a prior same-commit run already confirmed as true dead code (the TP cache), and a residual pool. A pool of triage-investigator sub-agents (Sonnet) investigates the residual, each emitting one self-contained TriageVerdict — tp, fp-novel, fp-classifier-regression, or uncertain. Finalize folds every verdict into one published, schema-v5 triage_results/<run-id>.json — the single cross-skill seam. Triage reads the registry as a filter but never writes it.

Classify — plan

Plan is an offline, planning-only engine over the published novel_issues[] rows. Group flattens each novel issue into evidence and buckets it by AriadneFaultArea — a folder-anchored, recomputed-on-read taxonomy of which part of core is at fault — consulting the membership-override store for re-routes. Strategize runs one plan-strategist (Opus) per bucket, which reviews every member's membership and emits a validated StrategistPlan tree with a core_fix_effort estimate. Reconcile flattens accepted plans into PlanTask rows keyed by a content-addressed dedup_key, augmenting rather than duplicating, retiring orphans whose bug appears fixed, and recording mis-route corrections. Plan writes only its own task-DB under ~/.ariadne/plan/.

Actuate — human

The autonomous sweep proposes; only a human promotes. The prioritize skill is the decision surface; the export_to_backlog.ts adapter — the sole writer of backlog/ — graduates selected tasks into backlog/tasks/<id>.md, stamping each with its plan_dedup_key. The human likewise owns every registry transition: authoring a wip rule, flipping it to permanent (regenerating the bundled core slice), or to fixed once a landing commit's fix(<task_id>) scope matches the rule's backlog_task.

Loop closure

Three surfaces are written in one run and re-read on the next. The registry → triage heal: a wip/permanent rule suppresses that false-positive class on the next run's filter. The triage_results → next triage TP cache: confirmed true positives at the same commit are reused instead of re-investigated. The plan task-DB + override store → next sweep: dedup_key lets the sweep augment instead of duplicate, and recorded mis-routes re-route members correctly. The backlog's plan_dedup_key frontmatter stops plan re-proposing promoted work; the git log ties each landed fix back to the rule it closes.

Three invariants hold the system together.
  • Single-writer ownership — each shared surface has exactly one writer: the human owns the registry, Reconcile owns the task-DB, the export adapter owns the backlog. Structurally enforced; see Write Boundaries.
  • Strict, versioned wire contracts — triage_results at schema v5, PlanTask at v1, StrategistPlan at v1; each parser rejects on mismatch, with no migration shims. See Schemas & Stores.
  • Recompute-on-read — evidence stores raw fault signals only; AriadneFaultArea is always derived against the current taxonomy, with other as the escape hatch. See Fault Areas.
