The Self-Healing Loop: Sense, Classify, Actuate

orientation read this first

The premise: every false positive is an Ariadne defect

Ariadne's job — the top of its intention tree — is to detect call graphs and thereby find a codebase's entry points. Doing that well means correctly distinguishing genuinely-unreachable code from code whose callers the resolver simply failed to connect. When Ariadne flags a function as an unreachable entry-point candidate and a caller actually exists, that is not noise to be filtered: it is a defect in Ariadne's own resolution, and it is the unit of work this whole pipeline exists to find and fix.

The framing that makes the system make sense: a false positive = an Ariadne bug. The self-healing pipeline is the operational loop wrapped around the core engine that systematically surfaces those bugs, groups them into actionable engineering work, lets a human decide what to fix, and then re-reads what it learned on the next run so the same false positives stop recurring.

The loop at a glance

The chain is three links — triage senses, plan classifies, the human actuates — stitched together by durable surfaces that survive between runs. Each run is self-contained and pinned to a target commit; the learning lives entirely in the surfaces.

The three links

Triage — sense

A self-contained per-commit job. Calls @ariadnejs/core to detect entry-point candidates, partitions them into auto-classified (an existing registry rule explains them), previously-confirmed TPs (the cross-run TP cache at the same commit), and a residual pool investigated by a pool of triage-investigator sub-agents. Finalize publishes one schema-v5 triage_results/<run-id>.json — the single cross-skill seam. Reads the registry as a filter; never writes it.

Triage (Sense) · Investigator

Plan — classify

An offline, planning-only engine over the published novel_issues[]. Three passes: Group buckets every false positive by AriadneFaultArea (which part of core is at fault), Strategize runs one Opus strategist per bucket to design a hierarchical fix tree, Reconcile flattens accepted plans into PlanTask rows keyed by a content-addressed dedup_key — augmenting, retiring, never duplicating. Writes only its own task-DB under ~/.ariadne/plan/.

Plan (Classify) · Fault Areas

Human — actuate

The deliberate, write-fenced end of the loop: the sweep proposes; only a human promotes. The prioritize skill previews proposed tasks with --dry-run, then drives export_to_backlog.ts — the sole writer of backlog/. The human also owns every classifier-registry transition (wip → permanent / fixed) and lands the actual core fix.

What "sensing" decides per candidate

Each investigated entry yields exactly one self-contained TriageVerdict:

VerdictMeaningIs it an Ariadne defect?
tpGenuinely dead code — the call graph is correctNo. Cached for reuse at the same commit.
fp-novelA real caller exists and no rule should have caught it — a detection gapYes. Published raw into novel_issues[]; the plan engine's input.
fp-classifier-regressionAn existing registry rule's predicate is too narrowA registry defect. Rolled up into classifier_regressions[] for the human's drift_evidence review.
uncertainEvidence is inconclusiveUnknown — published with its reason for audit.

Loop closure: how one run teaches the next

Three surfaces are written in one run and re-read on the next — this is the "self-healing" in the name:

#HealMechanism
1 Registry → next triage A wip/permanent rule the human authors from this run's findings suppresses that whole false-positive class on the next run's classifier filter — those entries are auto-classified and never reach an investigator.
2 Published results → next triage (TP cache) True positives confirmed at a commit are reused by every later run at the same commit instead of being re-investigated, amortizing LLM cost. Any new commit on the target busts the cache.
3 Task-DB + overrides → next sweep The dedup_key lets the next sweep augment an existing task instead of duplicating it; recorded membership mis-routes re-route members to the right fault area; and a task whose false positives stopped recurring is resolved — the bug appears fixed.

Two further read-only signals tie the ends together: the backlog's plan_dedup_key frontmatter stops plan from re-proposing work a human has already promoted, and the target repo's git log (task-scoped Conventional-Commits) is the audit trail by which the human flips a registry rule to fixed — no commit hash is ever stored.

The three architectural invariants

Single-writer ownership

Every shared surface has exactly one writer, which keeps the loop auditable: the human is the registry's sole writer (always through the locked atomic_update_registry), reconcile is the sole task-DB writer, and the export adapter is the sole backlog writer. An AST-level write-boundary test structurally enforces the registry boundary.

Write Boundaries · Registry

Versioned wire contracts

Every seam is gated by a strict, versioned schema with its own parser and no migration shims: the published triage results at schema v5, the PlanTask record at v1, the StrategistPlan agent output at v1. Mismatched payloads are hard-rejected; stale files age out naturally.

Schemas & Stores

Recompute-on-read

Evidence stores only raw fault signals (diagnosis strings, resolution-failure stage/reason) — never a stored fault-area value. The AriadneFaultArea is derived on every read against the current, folder-anchored taxonomy, so a forward-incompatible value routes to the other escape hatch instead of becoming a stored type lie.
