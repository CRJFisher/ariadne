Where the type is lost, and where the fix puts it back

The same pipeline carries a required param-property's type end-to-end, but for an optional param-property the implicit field is never created — so the chain breaks at the first hop and the member surfaces as a false-positive unreachable entry point.

Required works, optional does not — same AST, different query coverage

For a required param-property two modifier rules bind both @definition.parameter and @definition.field; the optional path has only a generic rule that binds a parameter and nothing else — the gap is in the .scm, not the AST.

the duplicate-capture nuance

The generic rule (line 432) and both new modifier rules match a modified optional param, so @definition.parameter.optional fires more than once for the same node — exactly as already happens for required params.

The downstream builder dedups by location-based symbol_id, so parameter counts cannot change; the tests assert exact counts to prove zero perturbation.
