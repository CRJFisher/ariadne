The defect in one sentence
Scope narrowing is applied at discovery, where it deletes call edges, rather than at candidacy, where it would only suppress questions; the compensation built to cover that loss is keyed on a narrower, drifting definition of the excluded region; and the single evidence channel counts declarations and comments as calls while being structurally unable to see a non-call reference at all.

Why the ordering is provably safe: the predicate deleted from discovery is byte-for-byte the predicate that already marks a callable is_test. Every file re-entering the corpus therefore adds edges and no candidates — verified empirically in Python and TypeScript. The TS fixture that today yields two false entry points yields an empty entry-point set with the caller back in the corpus.

Cost and blast radius

Core fix — small and surgical
  • Two deletions carry most of the benefit: a file_filter option with no non-test caller, and a substring match that becomes a segment match.
  • Hit qualification reuses a set the function already holds — no new regex, no language-specific def /function heuristics.
  • The reference axis is one pass over an in-memory registry — no re-parse, no I/O, single-pass invariant preserved.
  • Net code removed: two duplicate constant lists, a whole-repository second walk and re-read, two dead guards, one ad-hoc boolean and the precedence hack it drove.
  • No changes to the call-graph tier, the project loader's threading, or the test-file detector — this epic deletes the duplicates, not the owners.

Blast radius beyond the core
  • Type change cascades by design. Two new diagnosis members land in exhaustive record shapes, so every consumer becomes a compile error until it maps them — that error list is the work list for the consumer steps. One published field is deleted from the skill protocol, the triage output slice and the plan skill's store and grouping.
  • Two harness copies of the scope decision must be deleted together; one of them silently discards include_tests from project config today, so the two scripts currently build different corpora from the same config.
  • Two classifiers go through the registry lifecycle (human-owned re-staging) because their samples must be re-validated against the new evidence field; a third is re-validated because some of its members shift diagnosis.
  • One noisy sweep is expected and is not regression. With test call sites in the corpus many entries move to wrong-target — the resolver now genuinely sees the call and picks the wrong target. Read the sweep after, not during.
  • Reference-index size is the open measurement risk: the raw reference stream is verbose, and the identifier filter plus per-name cap are load-bearing for memory.
Scope explicitly held down. No general per-file candidate predicate is built (only two narrowings are in evidence, and the candidate tier already covers both). Angular component-template indexing is re-tiered out — it neither unlocks nor is unlocked by anything here and graduates as its own root. One leaf is deleted outright as false-premise, and three upstream fixes this epic's completed evidence exposes are re-homed to the epics that own them — this cluster carries those rows, not that code.

Why these two groups are one cluster

They are not merely adjacent. Read separately, they reach opposite conclusions about the same module — from the same code — and only one can land.

coverage_config said:
Make the corpus complete, therefore retire the compensation entirely — delete the module, its two fields, the fault-area member and its routing branch.
≠
entry_point_classification said:
Make the compensation complete and routed — rename it, widen its file set, and add a diagnosis that routes back into coverage_config.
The shared surface forces the merge. Both plans make identical deletions in identical places (the same field removed from the types package, the fault-area input, the plan skill's store and its grouping), both rewrite the same diagnosis function, and both edit the same three regions of the same harness script.

The settlement is the merged altitude: complete the corpus first, then complete the evidence over what remains. coverage_config is right that the test-directory compensation becomes provably empty, and wrong that the pass dies — after corpus completion a real residue remains (config excludes, scoped-out folders, files dropped on an indexing error). So the compensation survives, re-keyed off the only signal still true (discovered − indexed), and coverage_config stops being a judgement bucket and becomes a determinate route: the caller exists in a file we chose not to, or failed to, index.
Splitting them back apart costs a wasted implementation of whichever half lands second, plus a merge conflict on every shared edit site.
