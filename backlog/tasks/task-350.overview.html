Why one seam, not three patches

No exhaust_member_surface() indirection is added. The existing member_index fallback in resolve_method_on_type (L134–140) already is that surface.

Once the data is complete, the constructor and alias keys become ordinary name-keyed entries that every consumer — the regular-type fallback, walk_property_chain, polymorphic dispatch, the constructor site — discovers for free. Complete the data; don't add a layer.

The load-bearing invariant

The whole single-surface design leans on this one fact.

Constructor key — computed, not trusted

The constructor is keyed in member_index under its language-specific runtime name: __init__ (Python), constructor (TS), new (Rust).

ConstructorDefinition carries only name, with no language marker, and is not guaranteed to be the runtime invocation name — so WS1 must compute the key explicitly via a get_language_constructor_name helper, never trust ConstructorDefinition.name.

Collision-safe: reserved names cannot equal a user method, and interfaces never receive a constructor key — polymorphic and interface dispatch are unaffected.

Open questions — resolve before the workstream lands

Three must-answer points, each gating its workstream.

Does ClassDefinition carry enough class-body AST for the alias extractors to read literal assignments at index time? If not, WS2 expands to thread the assignment node from the tree-sitter query pass into the class factory.
O2 — default-import diff WS3
Does deleting resolve_named_import change default-import name-matching for any fixture relying on export default class X matched by name? resolve_export_chain keys default by ${file}:default. Diff before deleting; add a regression test if they differ.
O3 — ctor-name invariant WS1
