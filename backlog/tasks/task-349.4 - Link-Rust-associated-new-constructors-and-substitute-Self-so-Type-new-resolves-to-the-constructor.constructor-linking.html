The resolver edit — a path_prefix-gated, callable-only member-index link

The link lives in resolve_constructor_call: when the hierarchy walk returns null and the call carries a non-empty path_prefix, find_associated_constructor looks up new by the type id and returns it only when it is a callable kind.

constructor.ts — resolve_constructor_call (as built)
let constructor_symbol = find_constructor_in_class_hierarchy(
  class_def, definitions, resolutions
);

// Rust associated constructor: `fn new()` is stored as a plain method, so the
// hierarchy walk (which reads ClassDefinition.constructors) finds nothing.
// Gated to the Rust qualified path by path_prefix — the TS/Python
// `new ClassName()` path is untouched.
if (!constructor_symbol && call_ref.path_prefix && call_ref.path_prefix.length > 0) {
  constructor_symbol = find_associated_constructor(class_def.symbol_id, definitions);
}

return ok([constructor_symbol || class_symbol]);
constructor.ts — find_associated_constructor (callability guard)
const members = definitions.get_member_index().get(type_id);
const member = members?.get(RUST_ASSOCIATED_CONSTRUCTOR_NAME); // "new"
if (!member) return null;

// A field named `new` (struct T { new: ... }) overwrites the `fn new` method
// in the flat member index; only a callable target is the constructor.
const kind = definitions.get(member)?.kind;
return kind === "method" || kind === "function" ? member : null;
two guards keep the link Rust-only and field-safe

The path_prefix gate confines the link to qualified Rust calls, leaving the TS / Python new ClassName() branch untouched; the callability guard rejects a struct field named new that shadows the method.

Self::new() — substitute the enclosing impl type

A Self::new() call inside an impl carries name = "Self"; the resolver substitutes Self with the enclosing impl/trait type by walking the call's scope to its containing class scope, then resolves the constructor through the same member-index link.
