Two equally valid altitudes — pick one, do not double-count

Either populate constructors[] at capture time so the existing hierarchy walk finds new, or add the member-index fallback in the resolver. Both bind the constructor; the only hard constraint is that new is exposed exactly once.

the hard constraint — exactly one constructor target (AC #3)

A struct with one fn new must expose exactly one reachable constructor target. Option (a) risks counting new as both a method and a constructor; whichever altitude is chosen, new appears once, not twice.

Self::new() — substitute the enclosing impl type

A Self::new() call inside an impl carries name = "Self"; resolve Self to the enclosing impl/trait type by walking the call's scope to its containing class scope, then resolve the constructor as above.

Self bound and constructor resolved signature precondition reuses receiver_resolution.ts helpers
why this is independent of 349.1 and 349.5

Even with the type already bound in scope (use sync::Parker), the constructor link is missing — so this defect stands apart from the name-reduction of 349.1 and the inline-path walk of 349.5. It is the connective tissue: 349.1 carries the name, 349.4 makes the name reach the function.
