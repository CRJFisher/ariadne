TASK-362 · Information architecture · Refactor program

Execute the IA-review refactor program across core, types, and mcp

15 sub-tasks 2 tracks 4 dependency waves packages: core · types · mcp 362.1 started

Task 362 is a cleanup program for Ariadne's core code. A review found that while the top-level folders match the intended design, the code one level down has drifted: four oversized files each hide many jobs behind a single name, and the handling of "which programming language is this?" is scattered and inconsistent across the codebase. The program splits into fifteen sub-tasks along two tracks. The first eight (362.1 to 362.8) do the actual refactoring — unifying language detection, breaking up the oversized files, cleaning package boundaries. The last seven (362.9 to 362.15) harden the guardrails — hooks and rules that keep the newly-cleaned patterns from drifting back. The sub-tasks run in dependency waves; 362.1 goes first because it has the smallest blast radius, the highest citation count across the review, and it unblocks two other areas.

Settled rulings

Six decisions the sub-tasks apply, not reopen

Decided matters — contested recommendations already ruled on
  1. 1Keep dotted files. The {feature}.{lang}.ts mechanism is correct and hook-enforced; sub-tasks extend it, never replace it.
  2. 2No builtins renames. The check_* builtin filenames stay as they are.
  3. 3detect_language contract reconciliation. The three forked copies collapse to one nullable detect_language plus a throwing assert_language (362.1).
  4. 4MCP de-duplication. MCP imports build_signature / count_tree_size from core instead of re-implementing them (362.4 / 362.7).
  5. 5@language annotations in types. Deliberately-inline language branches carry @language comments rather than a dotted file.
  6. 6Registry group_id renames out of scope. The classifier registry keys are not touched by this program.
