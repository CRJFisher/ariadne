Triage TP cache: reuse only direct LLM verdicts, and find them across runs

190.22.16 Done 190.22.16.1 To Do priority high labels self-repair · bug parent TASK-190.22
Why this work exists

The triage pipeline caches confirmed-unreachable verdicts so that repeated runs at the same commit skip LLM re-investigation. The cache originally indexed every published row regardless of provenance, which laundered registry-suppressed entries past rule deactivation: an entry classified by a wip rule stayed "confirmed" even after a human marked the rule fixed, defeating exactly the re-examination the classifier lifecycle exists to enable. Restricting reuse to direct LLM verdicts fixes the laundering — and exposes a second defect in how the cache picks its source run.

● done · 190.22.16

Cache only direct LLM verdicts

One line in build_cache excludes registry and previously-confirmed-tp rows from reuse. Registry-classified entries return to the investigation pool the moment their rule is deactivated (marked fixed, or drift detected). Chained reuse rows are refused because the published schema carries no origin chain — a cache hit cannot prove its verdict traces back to a real investigation. No origin-tracking is added to the published schema.

if (fp.source.kind !== "llm-tp") continue;

Fall back through older runs at the same commit

The filter makes a reuse run's output useless as a cache source, but derive_tp_cache still consults only the single most recent run — so runs alternate forever between full LLM re-investigation and reuse. The fix iterates all finalized runs at the commit, newest first, and uses the first that yields a non-null cache, so the LLM cost is paid once per commit.
