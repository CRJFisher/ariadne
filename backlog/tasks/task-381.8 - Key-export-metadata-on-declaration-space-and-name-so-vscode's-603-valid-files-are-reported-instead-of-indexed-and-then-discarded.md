## Description

<!-- SECTION:DESCRIPTION:BEGIN -->

`ExportRegistry.update_file` keyed its metadata map on the export name alone and threw `Duplicate export name` when one name arrived twice, asserting in the message that this "indicates a bug in is_exported logic or malformed source code" about source that vscode's own build compiles. `load_project` caught it, rolled the partial index back and added the file to `dropped_files`, and the file then vanished from the report. On the landed tree that is **676 of 8,494 files (7.96%)** under vscode's `src/` tree — not the 603 the composed prototype dropped — and the whole population is one defect: the drop taxonomy over that arm is a single entry, `Duplicate export name "…" in file <path>` at 676. `Multiple default exports` fires on no file of this corpus.

The repair is now BUILT and measured at full corpus, not projected from withheld files. `export.ts` replaces the single `export_metadata` map with `value_exports` and `type_exports`, keyed by (declaration space, name); `declaration_space(def)` puts interface, type, type_alias and `import type` re-exports in the type space and everything else in the value space. That is exactly what `export const IFoo = createDecorator<IFoo>()` beside `export interface IFoo` means — two bindings of one name in two TypeScript declaration spaces — and it readmits all 676 of the files the gate discarded. Both throws are DELETED rather than flagged off: a second declaration in the SAME space is declaration merging, the first declaration keeps the metadata slot and the later symbol still joins the file's export surface, and the default slot takes the same first-wins rule. `get_export` must hand resolution one symbol for a name bound in both spaces, and it returns the member-declaring binding (class/interface/enum/namespace) over one that does not, preferring the value space otherwise, because `IUriIdentityService` then binds to the interface and `this.uriIdentityService.extUri.ignorePathCasing()` resolves instead of dying on a member-less decorator constant. The n=300 value-always A/B behind the earlier "4 more symbols, 0 lost, 2 fewer false entry points" was not re-run on this tree; the rule's three cases are guarded directly instead. `load_project`'s try/catch and its rollback are LEFT IN PLACE as a general per-file indexing-failure boundary and measured to fire zero times over `src/`; there is no flag, shim or parallel path. The loader now also carries each drop's reason, which is what lets the triage coverage gate report a count and an error taxonomy instead of ten paths out of hundreds.

The repair is bigger for the same CPU, and the "and faster" half is REFUTED on the tree it landed on. Over vscode's `src/` it adds 676 files, 16,638 nodes and 753,788 resolved call edges at 361.77 s against a 362.68 s interleaved control — 1.00x, two processes per arm in one session. The speedup the plan expected was the removal of 603 project-wide re-resolution cascades, and TASK-381.4's two-phase driver had already removed them: `Project.remove_file` is called ZERO times on BOTH arms, and `RECORDED_FULL_CORPUS_BASELINE` recorded that before this step ran. So the 2.202x and the 1.570x are both superseded rather than merely non-portable — they measured a cost that no longer exists. Peak RSS is likewise a property of the box: 6,911.75 MB candidate against 6,914.1 MB control on a 6-core Darwin 24.6.0 machine at a 12,336 MB cap, a -0.03% difference under run-to-run spreads of 5% and 7%.

The residual is 17 rather than 3, and only 3 of them are the classifier effect the earlier write-up described. Those three are exactly the sites it named — `reverse` at `rangeMapping.ts:51`, `mergeEditor/model/mapping.ts:74` and `:327`, raw candidates in BOTH arms. The other 14 are call sites that retarget onto an interface member: `lifecycle.ts` and `event.ts` are among the readmitted files, so a `.dispose()` call that previously had no `IDisposable` to bind now has one, and 11 `dispose` methods plus `TaskDefinitionRegistryImpl.onReady`/`.get`/`.getJsonSchema` lose their only incoming edge while keeping their node. The `TaskDefinitionRegistry` attribution the write-up called REFUTED is therefore back on a tree without TASK-381.11 composed, and the population is TASK-389.

Two populations the census does not cover are decided here, both verified against the corpus. Repo-wide the same key readmits Rust files whose items are `#[cfg]`-gated duplicates — `cli/src/util/os.rs` declares `pub fn os_release` at line 7 under `#[cfg(windows)]` and again at line 25 under `#[cfg(unix)]` — through the same-space "first declaration wins" branch. The TypeScript justification for that branch does not hold for Rust, so the module states the Rust rule as what it is: nothing in the source ranks the two variants and the indexer holds no build configuration to choose with, so the slot goes to whichever the file spells first, both symbols are exported either way, and the choice moves which one a name resolves through rather than what the file offers. And one same-space collision is an indexing bug the gate was masking, not legal merging: `editor/common/languages.ts` declares a namespace-local `const byKind` inside `export namespace CompletionItemKinds` at line 390 and inside `export namespace SymbolKinds` at line 1672, neither carrying its own `export`, and the indexer marks both `is_exported`. That is TASK-386.

This step's work is being verified and completed in a separate, human-directed session outside this run; this run does not attempt it.
