## Description

<!-- SECTION:DESCRIPTION:BEGIN -->

`ExportRegistry.update_file` keyed its metadata map on the export name alone and threw `Duplicate export name` when one name arrived twice (`packages/core/src/resolve_references/registries/export.ts:164-169`), asserting in the message that this "indicates a bug in is_exported logic or malformed source code" about source that vscode's own build compiles. `load_project` caught it, added the file to `dropped_files` and called `project.remove_file` (`packages/core/src/project/load_project.ts:263-265`), which re-resolved every dependent. The file had already been parsed, indexed and registered by then, so each drop cost a full index plus a project-wide re-resolution cascade and the file then vanished from the report: 603 of 8,494 files (7.10%) under vscode's `src/` tree, with 34,085 of 93,409 internal import edges pointing at one of them.

The repair is now BUILT and measured at full corpus, not projected from withheld files. `export.ts` replaces the single `export_metadata` map with `value_exports` and `type_exports`, keyed by (declaration space, name); `declaration_space(def)` puts interface, type, type_alias and `import type` re-exports in the type space and everything else in the value space. That is exactly what `export const IFoo = createDecorator<IFoo>()` beside `export interface IFoo` means — two bindings of one name in two TypeScript declaration spaces — and it covers 595 of the 603 files (633 constant+interface pairs, 47 interface+namespace, 24 namespace+type_alias, 3 constant+type_alias, 2 class+interface). Both throws are DELETED rather than flagged off: a second declaration in the SAME space is declaration merging (25 collisions across 14 files), the first declaration keeps the metadata slot and the later symbol still joins the file's export surface. `get_export` must hand resolution one symbol for a name bound in both spaces, and it returns the member-declaring binding (class/interface/enum/namespace) over one that does not, preferring the value space otherwise — measured at n=300 against a value-always variant, that choice reaches 4 more symbols, loses none, and removes 2 false entry points, because `IUriIdentityService` then binds to the interface and `this.uriIdentityService.extUri.ignorePathCasing()` resolves instead of dying on a member-less decorator constant. `load_project`'s try/catch and `Project.remove_file` are LEFT IN PLACE as a general per-file indexing-failure boundary and measured to fire zero times over `src/`; there is no flag, shim or parallel path.

The repair is bigger AND faster: at full corpus it adds 603 files, 12,069 nodes and 293,111 resolved call edges while costing less CPU, because the gate's real cost was never the dropped files but the 603 project-wide re-resolution cascades their rollback triggered after they had already been fully indexed. Two things the earlier write-up asserted are refuted by independent verification and must be carried as corrections rather than quietly dropped. The 2.202x speedup does not transfer: an independent verifier who built their own same-session control arm — reproducing this corpus's structural fingerprint exactly (7,891 indexed, 603 dropped, 183,018 nodes, 1,502,343 call refs, 26,610 indirect) — measured 1.570x for the composed stack, because absolute CPU for this workload is machine-bound. And the named residual regression is wrong: in the composed configuration the three extra classified entry points are three `reverse` methods (`rangeMapping.ts:51`, `mergeEditor/model/mapping.ts:74` and `:327`), which are uncalled and raw entry-point candidates in BOTH arms and differ only in the verdict of `enrich_call_graph`'s false-positive classifier — not `onReady`/`get`/`getJsonSchema` on `TaskDefinitionRegistryImpl`, and not the method-lookup gap that story attributed them to.

Two populations the census does not cover still need a decision here. Repo-wide the same key readmits Rust files whose items are `#[cfg]`-gated duplicates (`cli/src/util/os.rs` declares `pub fn os_release` twice, once `#[cfg(windows)]` and once `#[cfg(unix)]`; 8 such files in the first 200 discovered outside `src/`), through the same-space "first declaration wins" branch whose justification — TypeScript requires the substantive declaration first — does not hold for Rust. And one same-space collision in the census is an indexing bug the gate was masking, not legal merging: `editor/common/languages.ts` declares `const byKind` inside two different namespaces (lines 390 and 1672) and the indexer marks both `is_exported`.
