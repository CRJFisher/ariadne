TASK-190.22 · self-repair · architecture · restructure

Restructure the self-healing pipeline to triage → plan (planning-only)

priority high live subtasks done 13/13 follow-ups open .15–.20 remaining gate real-data end-to-end run
Why this epic exists The self-healing pipeline (skills under .claude/skills/) had never run end-to-end, yet its architecture committed to fully automated fix delivery. This epic simplifies the pipeline around the part that delivers value first: detect, then plan. Code mutation and loop-closure become manual, human-driven steps; the superseded automated fix-delivery design (TASK-190.18.*) is archived.
<\!-- ============ PIPELINE SHAPE ============ -->

The pipeline this epic builds

Two autonomous stages produce plans; every write into the human's world is a deliberate human act. The curator's code-mutating machinery is gone — the plan skill reads, groups, strategizes, and reconciles, and nothing more.

autonomous sweep human-invoked machinery removed data at rest

One typed package — @ariadnejs/skill-protocol — is the source of truth for the triage→plan seam (one schema version, run-id + path helpers), replacing duplicated constants and ../../../ registry-path traversal.
