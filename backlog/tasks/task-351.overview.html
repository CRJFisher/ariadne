Reachability through dispatch channels the static call graph cannot see

An entry point is declared on one structural fact: the symbol has no resolved incoming call edge. But many reachable functions are invoked through non-call channels — framework registration, runners, stored callables, codegen, closures. Today 65 per-language builtins patch this; their language skew is the bug.

Model dispatch reachability as one language-general data record on the candidate plus a few declarative predicate operators that read it — never as more imperative per-language builtins.

65 builtins today skew ~38 TS · ~22 JS · 1 Py · 0 Rust ~20 absorbed into one axis 6 sub-patterns 1 new record · DispatchSignals

The static call-graph blind spot

detect_entry_points sees only resolved call expressions; six dispatch channels invoke functions without one, so every such function surfaces as a false-positive entry point.

Why the boundary holds by construction

The new DispatchSignals record carries only positive dispatch evidence and deliberately omits resolution_failure, receiver_kind, and ariadne_call_refs. A resolver-miss fingerprint is therefore inexpressible as a dispatch rule — the split above is enforced by the type surface, not by reviewer discipline.

The load-bearing design rule

One type decision keeps the dispatch axis and the resolver permanently separate.

DispatchSignals carries only positive evidence

dispatch_signals is a separate field from DefinitionFeatures — which is JS/TS-gated by contract, the very gate that is the bug — and is populated by its own derive_dispatch_signals function so it can never inherit the is_jsts gate (extract_entry_point_diagnostics.ts:589).

Every dispatch rule gates on a present signal, never on the mere absence of a resolved edge. Resolver misses carry resolution_failure or grep hits the record does not expose, so they match no dispatch rule — a negative pre-emption test pins it.

Where the signals come from — and why most are nearly free

Three of the five operators read evidence the candidate already carries or that the indexer already extracts and merely drops; only one needs new machinery.

already present

is_anonymous · path · name

name === '<anonymous>' is already set for Rust and Python closures by the symbol factories; file_path and name are on every candidate. Pure reads — only the language gate is removed.

drop, then project

decorators

The indexer already populates definition.decorators for TS / Python / Rust; they ride on the candidate's node but are discarded at extract_metadata. Stop dropping them and project the names — pure projection, no resolver work.

bare_reference_sites

No value-read signal exists — today's grep index matches only the identifier( call form. A second inverted index matches the name not followed by (, scoped to definition-adjacent sites. Additive, hermetic, reversible — isolated to the last phase.

What makes the split work

351.1.7 · interim classifiers are mitigation only

Each interim wip rule suppresses its false positives until the core rule lands, then a human flips it wip → fixed via reconcile-registry. The axis makes the interim rules redundant channel by channel; core never writes the registry, so the lifecycle is unchanged.

Risks and open questions — resolve before each phase lands

Five points, each gating its phase; the bare-reference detector is the single riskiest, which is why it is sequenced last.

Bare-reference false positives 351.1.1
A name-keyed value-read index also matches shadowing locals, comments, and unrelated same-named symbols — over-suppressing real entry points. Constrain to definition-adjacent sites, require no-textual-callers as a precondition, and ship a same-named-but-unrelated fixture that must not be suppressed.
First-match-wins ordering all
A broad rule placed too high pre-empts narrower correct rules; too low, a surviving builtin pre-empts it. Cut over one channel at a time, delete absorbed builtins in the same change, and let the parity test catch any group_id drift.
Decorator name normalization 351.1.3/4
DecoratorDefinition.name may carry args / namespacing differently per language (@Component() vs @app.route('/') vs #[cfg(test)] vs #[tokio::test]). Pin the exact extracted name per language in data-layer tests before authoring any rule — never match source text.
is_anonymous completeness 351.1.2
If some Rust / Python closure form is not named <anonymous> by the symbol factories, it leaks. Verify against the 67 observed members' actual names with multi-form fixtures before declaring the pattern done.
Separate-function discipline all
derive_dispatch_signals must be its own function and field — copy-pasting the is_jsts gate from derive_definition_features would silently re-break Rust / Python, the exact bug being fixed. A Rust fixture asserting non-empty decorators is the tripwire.
Escalation path 351.1.1
If the hermetic grep index proves too coarse, escalate to broadening indirect_reachability to methods + field / hook / dict storage and surfacing it on CallableNode — a real resolve_references change, scoped as a follow-up, not part of this work.
