Root cause
The index records only edges that carry a name, the Rust path resolver fabricates files instead of resolving them, and the binder drops whole grammatical positions. Name lookup is starved at three independent producers — name_not_in_scope is the single shared symptom.
Verified altitude: the consumers are correct. resolve_scope_recursive builds its scope map correctly from the inputs it is given; resolve_export_chain's recursion is correct and cycle-safe. Both are starved, not mis-shaped — so the fix lands in the producers.

Why these two groups are one cluster

Not thematic adjacency — they collide on two literal surfaces and would otherwise be written twice, in conflicting orders.
Collision 1 — the else arm of resolve_module_path_rust
Three fixes land in one ten-line function, with a mandatory order: name_resolution rewrites it for 2018-style module directories, import_resolution adds a crate-roots lookup after the local probe, and scope_construction hands over the empty-module-path case. If the local probe is not correct first, the crate branch silently absorbs local misses — a wrong answer that still looks resolved.
Worse, import_resolution re-signs that exact function (root_folder → ModuleResolutionContext) while name_resolution introduces a new caller of it. Designed apart, that call site is written against a signature that is about to change.
Collision 2 — the module surface both read through
name_resolution's file hop terminates in resolve_export_chain with a root-scope fallback for non-pub items — the same function import_resolution is adding the wildcard fan-out to, and the same fallback type-model-completion needs. One surface, one design. Its signature is unchanged, so every existing caller inherits the fan-out for free.
Bonus — a naming collision settled
Two groups independently designed the same map under two names (wildcard_reexports vs star_sources) with opposite capture strategies for JS/TS. This cluster owns the surface; type-model-completion keeps only the consumer collapse.

Cost and blast radius

Contained
  • resolve_export_chain's signature is unchanged — consumers inherit the fan-out with no edits.
  • name_resolution.ts: one new arm. Its precedence chain stays byte-for-byte.
  • No new key on the scope map; NameResolutionResult and ImportGraph's shape are unchanged.
  • Rust mod binding is preserved by an existing guard — new imports are excluded from the scope index.
  • Sub-tasks 1–3 and 7 are each independently testable and independently valuable.
Wide
  • 33 non-test signatures swap root_folder for ModuleResolutionContext — mechanical, but it touches the whole import-resolution folder plus project.ts.
  • Six query (.scm) files and four capture handler modules change across all four languages.
  • Sub-task 1 deliberately converts a silent failure into a throw; the surfaced construct list is unknown until it runs (getters, static blocks, decorators, TS overloads, Python lambdas are expected).
  • New per-file memo on a hot barrel — TypeScript's _namespaces/ts.ts star-re-exports ~20 modules; benchmark before/after.

What this cluster does not buy

Read these before scoring the row count — they are already netted out of the ~266 figure where excluded, and flagged where uncertain.
6 rows excluded outright 5 Angular rows are a corpus bug, not an import bug — an unanchored substring ignore-match excludes every caller file. Re-homed to caller-evidence-and-corpus. 1 django row's only callers live in a deliberately excluded test tree.
2 tokio rows blocked tokio publishes its module tree from inside cfg_*! macro bodies, which index to zero definitions. The edge still lands; these rows need syntactic_extraction and must be excluded from acceptance.
~13 rows stay flagged Their recorded failure is name_not_in_scope (so this cluster owns the reference that failed) while the narrative describes polymorphic dispatch, getter reads, attribute-chain typing or dynamic dispatch. Not regressions.
1 true entry point A nest symbol with no in-repo caller — public API for downstream packages. Correctly flagged today.
Measure buckets, not counts For untyped JS parameters the failure moves forward from name_not_in_scope to receiver_type_unknown and re-routes to type-model-completion. And the split of 39 JS/TS/Python rows is not empirically established — re-run triage after sub-task 2 rather than predicting it.

How to rank this against the other clusters

Fund it if you want the run's largest row block and are willing to spend one cross-folder signature sweep to get it. Rust mod-path resolution alone (sub-tasks 7–10) is 177 rows and is the single highest-yield stretch of work in the run. It also unblocks a downstream cluster's 30-row leaf and settles a design collision that would otherwise be resolved twice, incompatibly.
Defer it if this run cannot absorb a 12-sub-task epic touching six query files, four capture handlers and 33 signatures, or if the deliberate new throw in sub-task 1 is unacceptable risk right now.
Partial funding The cluster splits cleanly along its two tracks. Track A (1–2) is small, independent, and lands the binder fixes plus a permanent class of silent bugs made loud. Track B track-head (3–5) is the piece type-model-completion is waiting on, and 3 alone removes the django whole-file indexing crash. The 169-row payload (9–10) requires the full Track B chain.
