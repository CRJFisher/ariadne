Self-repair pipeline · classifier drift · closing the loop

Reconcile-registry repairs a drifted classifier, one fixer agent at a time

Ariadne flags functions that look unreachable. Some flags are false alarms — the function IS called, through dynamic dispatch a static analyzer can't follow — so a small "classifier" predicate learns each false-alarm shape and suppresses it. Over time a classifier can start missing cases it once caught (drift). Today reconcile-registry only NOTICES drift and records the missed cases; a human then hand-edits the predicate. Task 190.36 closes that loop: after drift is recorded, it dispatches one focused agent per drifted classifier to repair its predicate. The hard part is a tug-of-war — widen the predicate to catch missed cases (recall), but not so wide it silences genuinely-unreachable functions the pipeline exists to surface (precision). So each agent captures only cases that are truly the same limitation, and escalates the rest.

Where this link sits in the self-repair chain

Triage publishes regressions; reconcile-registry records drift. This work adds the next link — a fixer agent that edits core's check_<group_id>.ts builtins, escalating to classifier-author for a different limitation.

The drift signal is mechanical and already lands; the missing link is turning each recorded miss into a repaired predicate without human hand-editing.

Why the fixer can't just broaden until every case matches

Recall and precision pull in opposite directions. Widening the predicate to catch missed cases is the tempting move — but each widening risks matching real unreachable functions, which are exactly the true-positives the pipeline exists to surface. The termination condition is the resolution, not a compromise.

The fixer agent's work loop

Each agent owns exactly one check_<group_id>.ts. It reads the rule's evidence, resolves each case to its full entry context, decides same-pattern versus different, and lands in one of the two termination states.

1

Read the evidence and resolve each case

Read the rule's drift_evidence[] and the current check_<group_id>.ts predicate, then resolve each case's full EnrichedEntryPoint — not just the one-line excerpt — via get_entry_context.ts, enabled by the schema change below.

get_entry_context.ts selector · .claude/agents/classifier-author.md :34-37 — --project --run-id --file --name --kind --line
2

Decide: same limitation, or a different one?

For each evidence case, judge whether it is the same permanent-limitation pattern the rule captures, or a genuinely different one that only looks similar in the excerpt.

3

Captured predicate edit

Broaden or correct the predicate so every same-pattern case matches; ship a test asserting the evidence cases now match and a negative guard asserting a known true-positive still does not match; rebuild core green.

4

Mis-classified escalate

Never stretch the predicate to cover a different pattern — that suppresses true-positives. Record which cases belong elsewhere, notify the user, and hand off to classifier-author for a novel permanent-limitation group.

The schema change that makes a case resolvable

A drift_evidence[] row carries only { entry_index, evidence_excerpt }, deduped by entry_index alone — it can't say which run the index came from. Adding { project, run_id } per row makes each case resolvable.

The riskiest guarantee

The skill never over-broadens silently — a case that cannot be captured without risking true-positive suppression is escalated, never absorbed. The predicate only grows to cover what is genuinely the same limitation; everything else routes to a human-owned classifier-author hand-off.

Where this converges

Once growable eval-sets exist (TASK-190.31.1 / .2), the fixer validates its broadened predicate against the rule's eval-set — precision and recall — before the change is accepted, so a fix that buys recall at the cost of precision is caught mechanically rather than by the agent's own judgment.
