Self-repair pipeline · entry-point classification

Finding the codebase's true entry points — and teaching the tool its own false alarms

Ariadne traces call graphs to find a codebase's real entry points. Functions with no caller look like entry points, but many are reached indirectly — stored in a field, passed as a callback, dispatched from a collection.

TASK-190 builds a pipeline that detects these false positives, investigates each, and lands the core fixes so the analysis improves itself.

parent of 24 sub-tasks depends TASK-189 priority high

The five-phase loop

A single Claude Code session drives a deterministic state machine: detect false positives, investigate each in its own context, plan a fix, and land it. Bash phases carry no LLM; a stop hook advances the state file between phases.

Where TASK-190.28 lands

190.28 is a phase-5 core fix: two TypeScript false positives that survived detection get corrected at the indexing layer so the call graph stops reporting them. After they land, the human retires the matching classifier rows — closing the loop the pipeline exists to close.

Where TASK-190.33 lands

Phase 5 flips a classifier row when a fix lands — a human-owned registry write. 190.33 makes that ownership real in the repo: an in-repo PreToolUse hook routes every agent write of registry.json to a per-edit human ask, so an unattended agent can't silently rewrite the loop-closure surface even if the out-of-repo harness guard is off.

Where TASK-190.32 lands

When phase 4 finds a permanent limitation — a false positive fundamentally out of static reach — it routes the group to the classifier-author agent instead of the backlog. 190.32 wires that authoring path end-to-end: the agent can now fetch each sample by the stable member_symbol prioritize holds, so a permanent-limitation group actually reaches the agent and produces a staged classifier draft for the human to apply.

Where TASK-190.34 lands

Phase 4's plan stage marked classifier groups with a boolean that assumes a core fix always exists — it couldn't name a permanent limitation (no core fix; → registry via classifier-author) apart from ordinary core-fix work (→ backlog). 190.34 gives StrategistPlanNode/PlanTask an is_permanent_limitation flag and purges the interim-classifier concept, so step 3a routes on data.

Where TASK-190.35 lands

The registry's classifier once carried a kind tag choosing between a stub, a real check, and a retired check — but the catalog is now entirely real checks (18 builtins, one inert stub, no retirements). 190.35 flattens the tag away so every classifier is a plain { function_name, min_confidence }, converts the lone stub into a firing check, and makes retirement delete the row (git history is the audit) rather than mark it in place.
