Record the scope's self type as LexicalScope.self_type_name

wave 1 · no dependencies first reader TASK-376.5 4 boundary extractors 13 capture shapes

Ariadne works out which type self, this or cls stands for by scanning backwards from a method to its owning class, which finds nothing for a Rust impl block whose type lives in another file; this step records the type on the scope instead.

Where the answer comes from

A backwards scan at query time, replaced by a field written once

Capture shapes

What each captured node records, and where name runs out

Pinned decisions

What the field means, and what stays as it is

  • ▸self_type_name holds a name resolvable in the scope that records it, not a resolved symbol id.
  • ▸PythonScopeBoundaryExtractor implements the extractor interface directly rather than extending the common base, so Python needs its own implementation, not an override.
  • ▸extract_scope_name stays unchanged — name keeps meaning the scope's own identifier, and a Rust impl block has an owner rather than a name.
  • ▸A Rust impl block stays a block scope, because scope.type feeds boundary sorting and containment; the new field carries the fact instead.
  • ▸Nothing reads the field yet — TASK-376.5 is the first reader, so this step is testable at the single-file indexing tier alone.
