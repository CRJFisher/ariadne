What changes

A receiver-directed call needs five facts. Ariadne records none of them — each is re-derived at the point of use, by two or three drifting builders, from raw source text. The five member fault areas are those five facts.

Before — five facts, re-derived at the point of use
Fact needed Derived by (competing builders) How it fails
1. The annotation
what a name denotes		 6 sites hand raw annotation text to a bare Map lookup, unparsed Resolves only if the text is byte-identical to a declared name. &mut S, Option<T>, F | null, Optional[C] all miss
2. The scope's self
what self/this binds to		 Not stored. find_class_from_scope runs the member index backwards from the first method it finds Five independently reproduced failure modes; the scan breaks on the first candidate, so each is fatal
3. The value
what a binding holds		 No channel exists — only a type channel and a call-target channel cls = Parser; cls() → receiver_type_unknown
4. The member set 3 builders — one live, one whose maps are dead, one reachable only from tests Live one is per-file set, so a Rust type with impls in several files keeps only the last; enums get no index at all
5. The subtype graph 3 builders — two forward, one inverse, each with a different source of truth Drops qualified TS heritage, every Rust trait edge, every base past the first, and every edge whose caller was resolved before the implementer was ingested
All five gaps arrive at one sink: the member probe in method_lookup.ts:132-138, which reports method_not_on_type. Each builder's gaps are a different population of false positives, which is why the same defect surfaced as five separate fault areas.

Why this stays one epic

The five groups were not merged for convenience. Read together they were designing one type model in five places, and in four places they designed the same mechanism twice with incompatible shapes. The merge settles each conflict.

Collision Competing designs Settlement
Where Rust annotations are normalised Destructively at index time (method_lookup) vs. parsed at resolve time (receiver_type_inference) Resolve time. The index-time strip discards exactly the type arguments two other members need, and unwrapping is a policy decision.
How a scope names its self type Field on the method definition vs. field on the scope The scope field. A cross-file Rust impl contributes zero definitions, so a definition-carried field cannot exist to be read.
registries/type.ts STEP 3 Three groups want three different things: delete it, rewrite it, or reshape the maps it writes Delete it. Heritage resolves once, in the single builder, publishing both directions.
The value channel Three designs for one channel — same two consumers, overlapping producers One union in call_resolution/value_source.ts, with the union of all three producer sets.
The tradeoff, stated plainly
Splitting this into two smaller epics would give you two fundable units instead of one — but it would leave two epics racing on the same two edits: registries/type.ts STEP 3 (one epic deletes it while the other rewrites it) and find_class_from_scope (one deletes it while the other still depends on its behaviour). Whichever landed second would be rebasing onto a type model it did not design. The consolidator kept it as one epic to avoid that — the size is the price of not having a merge conflict on the core of the resolver.

Work order — 17 strictly-ordered sub-tasks

Each step is independently verifiable, and each de-noises the measurement of the next.

Risk Shape and mitigation
HIGHEST
Splitting symbol_types		 The conflation of value type and return type is what makes chained receivers resolve today. Every read site must be re-aimed in the same change or chains regress silently. Existing chain tests are the gate.
Fan-out precision Making interface annotations resolve hands the resolver far more receivers; rung 5 fans a common name (save, run) to every subtype. Trades false positives for false negatives — measure edge-count deltas after 6 and again after 14 before assuming pure gain.
Structural-match floor A one-member interface would match every class with that member. Measure the false-edge rate before fixing the constant; consider requiring ≥2 methods.
Incremental correctness The member-index union changes eviction semantics (needs per-file provenance), and the pending-failure index leaks across an incremental session unless evicted on successful re-resolution.
Rust unwrap list Option<T>/Box<T> unwrap, Vec<T> must not. Fixed short list, but the one place a wrong entry produces a false positive rather than a miss.
Decision summary
This cluster owns the single defect responsible for more false positives than any other in the run, and fixing it makes method_not_on_type mean what it claims to mean. It is also the only cluster that cannot be part-funded through its middle: sub-task 6 is one indivisible commit that gates nine others.

If you fund one thing here, fund sub-tasks 1, 2, 3, 4 and 7 — small, independent, no dependency on the chain, and they make every other cluster's measurements honest. If you fund the epic, fund it whole, because splitting it re-creates the two-epic race on registries/type.ts STEP 3 and find_class_from_scope that the consolidation exists to prevent.
