The crux: the producer alone is not landable — it regresses shadowing

Reducing utils::helper() to the bare name helper makes it indistinguishable from a local helper(). In the shadowing.rs fixture a local fn helper shadows use utils::{helper} — so the qualified call collapses onto the local shadow. The path-prefix resolver that honours the qualifier is what keeps them apart; the two are one task.

Where name is born — the reference builder, one altitude above Phase-1

By the time Phase-1 runs, name already equals "worker::create" — a string no bare-name scope map can hold. The fix belongs in the reference builder, where name is first assigned.

removed fallback (Rust qualified calls) new path-prefix extractor terminal name + prefix attached
why the TS/JS fallback is untouched — no TS/JS regression

The capture.text fallback switch (references.ts ~563) only handles TS/JS call_expression / new_expression, so the terminal-name refinement leaves it inert for those — only Rust qualified calls change. Do not add a bare-identifier branch: the test "returns undefined for non-call nodes" depends on a bare x staying undefined.

path_prefix is held apart from property_chain — not overloaded

A dedicated path_prefix?: readonly SymbolName[] field is added to FunctionCallReference and ConstructorCallReference rather than reusing property_chain: two TS-oriented consumers bake in the [namespace, class] index convention and would mis-bind a Rust type-last chain.

FunctionCallReference has no property_chain field today; ConstructorCallReference.property_chain stays unset for Rust. The field is additive — no schema bump (per project memory project_plan_pipeline_no_schema_bumps).

Function-call resolution — resolve via the path first, honour the qualifier

When ref.path_prefix is present, resolve via the path first (the author wrote the qualifier), falling back to the bare terminal only on a path miss — sound by construction, avoiding the unsound global get_definitions_by_name ambiguity scan.

module-qualified path type-qualified path gate bypass guarded by prefix
collision safety — the prefix is enforced, not assumed (AC #5, #6)

The retained path_prefix is the disambiguating guard. When the terminal is ambiguous (a local shadow, or two in-scope modules/types exposing the same name) the prefix selects the target — evaluated in scope, not via a global name scan, because the single-valued by_scope map collapses same-name bindings.

A bare unqualified call (no path_prefix) resolves exactly as before — the gate is bypassed only when path_prefix is non-empty.

Same-crate alias hops (use ll::Semaphore) ride this path only when the leading segment resolves through a same-crate use/type alias; a cross-file re-export is import_resolution — bail rather than fabricate an edge.

excluded — the TS static-dispatch row (epic AC #5)

LanguageServiceTestEnv.setup() is captured as a MethodCallReference (is_method_call returns true for a member_expression callee) on the method-lookup lane — it shares no mechanism with the terminal-name path. Excluded to method_lookup, not folded here.
