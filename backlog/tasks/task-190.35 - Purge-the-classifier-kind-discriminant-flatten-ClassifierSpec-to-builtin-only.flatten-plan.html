Self-repair pipeline · classifier catalog

One shape for every classifier: flattening the kind tag away

The registry catalogs call relationships that static analysis can never resolve — a callback dispatched through a computed key, a function reached only through a macro. Each entry carries a small classifier that recognizes the pattern, tagged with a kind that could be one of three things: none (a stub with no check), builtin (a real check function), or retired (a fixed bug's former check, kept for the record). In practice the catalog is one thing: 18 of the 19 live entries are builtins, one is an inert stub, and no entry is retired. This work removes the tag and makes every classifier a plain check — a function name and a confidence threshold — so the code stops branching on a distinction that no longer distinguishes anything.

03Retirement flips from mark-in-place to delete-the-row

This is the one genuinely subtle change. The retired kind was added on purpose so a fixed bug's from.function_name would not dangle after its check_*.ts was deleted. Removing the kind means a fixed classifier can no longer linger — so retirement deletes the row and its check file outright, with git history as the audit trail.

Why this is the delicate part

The retired kind exists to solve the dangling-name problem: once a fix lands and its check_*.ts is deleted, the row's function_name points at a missing file.

So retired parks the former spec in from on a non-firing fixed row. Deleting the variant re-opens that problem — and the answer is to delete the row too: no lingering row, no name left to dangle.

The fixed status then becomes largely vestigial (a fixed bug is an absent row) — a follow-on, out of scope here.

06What is traded, and what is bought

The accepted trade

Given up: the in-registry, lossless retirement audit — a fixed bug's former from spec and reason preserved on a durable fixed row.

Bought: a type with one shape instead of three, five files that stop asking “which kind?”, and a catalog where every entry carries a real, firing check — including the lambda-handler row that was dead weight.

The retirement record moves from the registry to git history: the commit that deletes a row is the audit trail. Accepted per the task request.
