The failure

Why this is high priority A routine failure — one strategist of N producing a missing or validation-rejected plan — makes the reconcile pass flip every live task in that strategist's fault area to resolved, with false resolve sweep events, while the false-positives that justify those tasks still sit in the bucket file. Only the plan failed; the underlying issues did not go away. State self-repairs only on the next fully-successful sweep.
1

A fault area contributes zero candidates

load_staged_plans iterates only the plan files that exist under staging/<sweep-id>/plans/. A validation-rejected plan lands in rejected[] and is skipped; a bucket whose plan file was never written is not even reported — it vanishes silently. Either way the area produces no PlanTask candidates.

.claude/skills/plan/src/reconcile/load_staged_plans.ts :72–103
2

The retirement gate never asks about fault areas

retire_orphans treats any live task that is unclaimed by a candidate AND whose projects were all scanned this sweep as stale. Both conditions hold for the failed area's tasks — its candidates never arrived, and the projects were swept. There is no per-fault-area condition.

.claude/skills/plan/src/reconcile/reconcile_plan.ts :290–298
3

Live planning state is destroyed

Nothing in the area overlaps a fresh create, so every orphan falls through to the resolve branch — "the false-positives stopped recurring" — and gets a terminal status flip it never earned.

.claude/skills/plan/src/reconcile/reconcile_plan.ts :362–366

Sweep with the project-only gate

Three fault-area buckets enter Pass C. One plan validates, one fails validate_plan, one was never staged. Follow each lane left to right — the bottom two lanes end in false terminal flips.

Sweep with the fault-area gate

The same sweep under the fix. load_staged_plans reads the buckets directory as well as the plans directory, so a bucket with no plan file becomes a rejected[] entry instead of vanishing — and the loader returns the set of fault areas whose plans were accepted. retire_orphans retires only inside that set.

The gate

The orphan filter gains exactly one conjunct. The project gate already protects against partial-scope sweeps (--project, --last); the fault-area gate protects against partial-plan sweeps. Both are needed — they guard different failure axes.
