04The one disposition that creates work before it deletes

Remove-deferred-untracked is the riskiest step: these classifiers fire because the pattern is real and high-volume, but nothing in the backlog drives its fix. Delete it carelessly and the signal vanishes — the pattern resurfaces as fp-novel forever with no task behind it.

⚠ task-first, then delete — never the reverse

For each untracked entry: author a new backlog task for the underlying Ariadne bug (real, observed, high-volume), set its id as the entry's backlog_task for the audit trail, and only then delete the entry. The backlog task is the deliverable; the deletion is cleanup.

1

Identify untracked entries from the disposition map

Authored classifier (kind = builtin or predicate), pattern judged fixable, and backlog_task is empty.

2

Author one backlog task per entry, before any registry write

File under the right parent (e.g. TASK-190 for resolution gaps); document what the bug is and at what altitude the fix belongs.

3

Record the new task id, then delete the entry

Set the new id as backlog_task in the disposition map before removal, so the audit trail survives the deletion.

acceptance gate

"No deferred-feature classifier is removed without a tracking task in place." Every untracked entry has a new backlog task created before the entry is deleted — this is a hard checkbox on the task, not a best-effort.

06Execution order — and where the writer contract binds it

Strict sequence: produce and review the map, create tasks for untracked entries, promote, then one bulk delete. The human is the registry's sole writer; every mutation goes through atomic_update_registry, never a bare writeFile.

1

Build the disposition map, then review it

A scratch (uncommitted) script reads registry.json and emits {group_id, kind, status, backlog_task, has_classifier, proposed_disposition, rationale} for all 170. No writes happen until the map is reviewed.

scratch script · output reviewed before any mutation
2

Author backlog tasks for every Remove-deferred-untracked entry

This happens before any registry edit so nothing is deleted until tracking exists. Record each new task id back into the map.

backlog/tasks/ · the §4 safety rule
3

Promote the ~14 impossible-pattern entries

Sanity-check each classifier still identifies its pattern, then reconcile_registry.ts --id <group_id> --promote — flips to permanent and regenerates the bundled core slice.

.claude/skills/triage/scripts/reconcile_registry.ts
4

Bulk-delete stubs + deferred in a single atomic transaction

One atomic_update_registry mutation removes all Remove-stub / tracked / untracked entries — not 150 separate writes. Dry-run summary first; apply after review.

packages/skill-fs/src/atomic_update_registry.ts · one .lock-guarded txn
5

Delete orphaned builtins and de-register them

Any check_*.ts whose function_name no longer appears in any entry is deleted from builtins/ and removed from builtins/index.ts. No deprecation shims.

Regenerate permanent_data.ts and run the gates

the binding constraint

plan and triage never write the registry; only the human does, through atomic_update_registry. registry_writers.test.ts is an AST walk that fails the build if any site calls a raw write against a registry-shaped path — so even step 4’s bulk-delete routes through the helper.
