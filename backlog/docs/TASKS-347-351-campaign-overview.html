entry-point detection · false-positive campaign · one pipeline run

Five root causes behind one symptom: reachable functions reported unreachable

Ariadne traces call graphs to find a codebase's entry points: a function with no resolved incoming call edge is reported as one. Five upstream defects make that edge go missing on functions that are reached — tasks 347–351 each close one channel.

Four tasks make a missing-but-real edge appear; the fifth recognizes the candidates where no static edge can ever appear. Together they partition the false-positive population by design.

5 root causes 1 quality defect ~600 confirmed false positives 19 projects 3 execution phases

The unifying theme — one defect, two families

Every task attacks the same end symptom along one fault line: make the missing edge appear (the call is statically resolvable but the resolver is starved of a fact) versus recognize no edge can ever appear (the function is reached through a channel the static graph cannot represent).

Family A adds edges (resolution_count 0→>0) Family B interprets the absence of an edge

Pipeline map — where each task lives

The core pipeline has three stages. Family A's four tasks add edges across stages 1 and 2; 351 sits at the terminal stage 3 and reads the final candidate set, after 347–350 have done their work.

dashed = the same task spanning stage 1 capture into its stage 2 consumer solid = resolved-edge handoff into stage 3
The resolved-edge handoff chain

347 keys a type-keyed surface → 350 completes it → 349 selects which type to look in → 348 binds the names so the lookup starts. All four raise resolution_count from 0; 351 interprets whatever candidates still carry no edge.
