Ariadne Self-Healing Pipeline — Architecture

Two read-only skills — triage (sense) and plan (classify/plan) — feed a manual human actuate stage, with a human-maintained classifier registry closing the loop into the next run.

The self-healing loop (end-to-end)

The pipeline is two read-only skills — triage (sense) and plan (classify/plan) — feeding a manual human actuate stage; four durable surfaces survive between runs, and the human-maintained registry closes the loop by filtering the next triage run.

Triage — sense

Triage: Detect → Prepare → Triage Loop → Finalize

The triage skill runs four phases per invocation: detect entry points, classify them against the human-maintained registry into three buckets, investigate only the residual with a worker pool of sub-agents, and publish a self-contained v5 results JSON.

triage-investigator: one entry, one verdict

One investigator sub-agent hydrates a single entry's context, checks it against the read-only registry slice (early-exiting to fp-classifier-regression on a rule match), then probes reachability via the call graph and emits exactly one of four verdicts to results/<entry_index>.json. It never writes the registry.

Plan — classify / plan

Plan — group → strategize → reconcile

The plan skill turns finalized triage runs into firewalled PlanTask rows in three passes — group every false-positive into fault-area buckets, strategize one opus plan per bucket, then reconcile trees into the task-DB by dedup_key. A separate human-invoked export adapter is the only sanctioned crossing into the user's backlog.

Reconcile: flatten the strategist's plan tree, key it, fold it into the task-DB

A re-sweep flattens the strategist's fix-plan tree into PlanTask rows, stamps each with a content-derived immutable dedup_key, then reconciles against the live task-DB — a colliding live task is augmented in place (never duplicated), unclaimed orphans are superseded/combined/resolved, and tasks the user already promoted into backlog/ are marked exported. The JsonPlanTaskRepository task-DB and append-only sweep log are the persistent stores; the firewalled read of backlog/ frontmatter is the only window into the user's tracker.

plan-strategist: one bucket → a validated fix-tree in staging

For one deterministic fault-area bucket, the strategist hydrates context, authors a hierarchical StrategistPlan (architectural → fault_area → localized), then self-validates and iterates until clean, writing only into ~/.ariadne/plan/staging. It writes no code, registry, or backlog — and for an 'other' bucket it emits both a taxonomy-extension and a core-fix task.

Shared — contracts & enforcement

Shared contracts & write-boundary enforcement

The v5 triage_results schema is the triage-to-plan seam; two build-failing AST tests enforce that the only legal registry writer is the human via atomic_update_registry, and the only legal backlog/ writer is the export adapter. triage and plan are read-only against the human-maintained registry.
