Where name is born — the reference builder, one altitude above Phase-1

By the time Phase-1 runs, name already equalled "worker::create" — a string no bare-name scope map can hold. The reduction lives in the reference builder, where name is first assigned.

why the TS/JS fallback is untouched — no TS/JS regression

The capture.text fallback in references.ts only handles TS/JS call_expression / new_expression, so only Rust qualified calls change. A bare identifier is left unhandled by extract_call_name, so it returns undefined and the fallback preserves Self / Config.

path_prefix is held apart from property_chain — not overloaded

A dedicated path_prefix?: readonly SymbolName[] field is added to FunctionCallReference and ConstructorCallReference rather than reusing property_chain: two TS-oriented consumers bake in the [namespace, class] index convention and would mis-bind a Rust type-last chain.

FunctionCallReference has no property_chain field; ConstructorCallReference.path_prefix is produced now but consumed by 349.4 / 349.5. The field is additive — no schema bump (per project memory project_plan_pipeline_no_schema_bumps).

Function-call resolution — resolve via the path first, honour the qualifier

When ref.path_prefix is non-empty, resolve_function_call (:324) calls resolve_via_path_prefix (:55) before any bare lookup; on a path miss it falls back to the bare terminal. A leading crate/self/super anchor is stripped first.

type-qualified (member index) module-qualified (mod body / use import) path miss → bare fallback
collision safety — the prefix is enforced, not assumed (AC #5, #6)

Ambiguity is evaluated in scope, not via a global name scan: the single-valued by_scope map collapses same-name bindings, so the import path is matched segment-wise and two distinct in-scope matches are treated as a collision (a miss), never silently first-won.

The bare find_function_resolution path is unchanged: a type-qualified associated function (kind:"method") binds inside resolve_via_path_prefix and returns before the method-rejection gate is reached, while a bare make() still hits that gate. The path-prefix lookup additionally requires the matched member to be callable (is_callable_definition).

excluded — the TS static-dispatch row (epic AC #5)

LanguageServiceTestEnv.setup() is captured as a MethodCallReference (is_method_call returns true for a member_expression callee) on the method-lookup lane — it shares no mechanism with the terminal-name path, and is handled in method_lookup, not here.
