Change group · false-positive unreachable-function flags

Receiver types are dropped at indexing, not resolution — three feeder fixes close the gap

Methods reached only through this.field.m(), self.attr.m(), or a JSDoc-typed param are flagged unreachable because the receiver's declared type never reaches the registry. The resolver is already correct; the loss happens in three indexing feeders across three language surfaces.

Three independent fixes — distinct languages, distinct files, parallelizable

No shared cross-folder pass, no duplicate builder. Each fix lives in one capture/extractor file at the indexing altitude and can ship in any order or in parallel.

Optional ctor param-properties emit their class field

Required param-properties promote to a class field; an optional one (config?: T) is an optional_parameter node with no @definition.field capture, so the implicit field is never indexed.

FIX BJavaScript

Associate JSDoc @param {T} name with the param

extract_jsdoc_type matches only @type / @returns. A param typed purely in JSDoc gets no def.type, so resolve_identifier_base has nothing to resolve.

metadata_extractors.javascript.ts
// find enclosing JSDoc, match by param name
const tag = jsdoc.match(
  /@param\s+\{([^}]+)\}\s+name/);
return tag?.[1]; // → def.type
// exact name match, no positional guess

Fund-or-not: benefit vs cost for ranking against the other six

Decision framing

Benefit: clears 34 observed false unreachable-function flags across 8 projects — roughly 28 members resolved by core fixes alone, the rest by the existing builtin and a narrowed interim classifier on the residual self-attribute row.

Cost: three small, independent, additive indexing-feeder edits — no resolver change, no data-model change, no cross-folder pass. Effort sits at the low end (3) for A and B; C re-tiers down from 5 to ~3. No deletions required.

Benefit34 FPs · 8 projects · ~28 members
Costeffort 3–5 · 3 files · all additive
Risklow — additive captures, regression-guarded
Arm split3 core fixes + 1 interim classifier (Shape I → 350.4)
Why this ranks high

High false-flag count for unusually low and well-bounded effort: the work is three localized producer edits in distinct files, every consumer already reads the populated fields, and the riskiest-sounding leaf (the effort-5 "cross-folder flow pass") does not exist and is not needed.

What this does NOT cover

The Cython-object self.obj row stays false until the narrowed interim classifier (TASK-350.3, now Done) is authored. The fixture-injected Styler row is a different diagnostic shape, deferred to TASK-350.4. The tokio index-operator row is a different fault area (syntactic extraction) and grounds no work here.
