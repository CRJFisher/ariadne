Why a dropped assignment becomes a false entry point

The property type built at indexing time is the first link in a chain ending in reachability. Drop the property and every stage starves: no receiver type, no call resolution, the method looks uncalled.

before — property dropped shipped — type carried the handler this task edits resolve & trace stages are unchanged — only the producer is edited

The three gates, before vs shipped

Gate 1 promotes from any direct method body; gate 2 takes the last segment of a qualified callee; gate 3 — added in review — admits only CapWords callees, so a transient call result is never recorded as a declaration. Gates 2 and 3 live in extract_constructor_rhs_type.

Why a syntactic proxy

Single-file indexing has no cross-file class table to confirm a callee is a class. PEP 8 CapWords (/^_*[A-Z]/) is the syntactic signal for a construction: Database() and _Private() type the attribute; helper() or obj.transform() stay transient.

First assignment wins; a typed assignment upgrades an untyped one

Widening gate 1 exposes a hazard: the same attribute is often assigned in several methods. add_inferred_property_to_class keys dedup on the attribute name, not location — so two assignment lines collapse to one property.

First-inserted (document order) wins. A later typed assignment upgrades an earlier untyped one; an existing typed value is never clobbered.

Promotion scope

Promotion is confined to direct method bodies — the nearest enclosing function must sit directly in the class block, so a self.x inside a nested function never leaks into the class. Control-flow blocks (if/for/with/try) inside a method do promote, since the enclosing function is still the method.

Namespace-qualified extraction mirrors an existing rule

Taking the last segment of a qualified constructor is not a new idea in this codebase — extract_constructor_bindings already does it for new models.User(). The shipped extract_constructor_rhs_type applies the same last-segment rule on the Python self-attr path.

A

Bare identifier — already handled

# function child = identifier
self.df = DataFrame()
# callee.text = "DataFrame" ✓
rhs_type = "DataFrame"

The function child is an identifier; its whole .text is already the type name (and passes the CapWords gate).

B

Attribute node — this fix

# function child = attribute
self.df = pd.DataFrame()
# whole .text = "pd.DataFrame" ✗
last segment = "DataFrame" ✓

Take the attribute field of the function node — the last segment — exactly as the parallel below already does for new models.User().
