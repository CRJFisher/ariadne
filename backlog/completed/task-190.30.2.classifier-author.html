the biggest divergence from the plan — the predicate DSL is gone

The task started with an agent that would choose predicate or builtin; it shipped with the predicate abstraction removed outright — the operators, the evaluator, and every consuming arm. The predicate DSL was the wrong abstraction, too brittle to type, so every classifier is now one small, directly-typed function.

Below: the pytest-fixture conversion, glob-as-regex intact.

packages/core/src/classify_entry_points/builtins/check_framework-pytest-fixture.tsas shipped
// A function decorated with `@pytest.fixture` is invoked by the pytest runtime
// when a test requests it — a legitimate entry point with no explicit call
// site. The pattern is passed to RegExp verbatim (glob-looking but regex):
// `@pytest.fixture*` reads `.` as any char and `*` as zero-or-more `e`.
import type { EnrichedEntryPoint } from "@ariadnejs/types";
import { detect_language } from "../extract_entry_point_diagnostics";
import { extract_decorator_block } from "./extract_decorator_block";

export function check_framework_pytest_fixture(
  entry_point: EnrichedEntryPoint,
  read_file_lines: FileLinesReader,
): boolean {
  const check_0 = detect_language(entry_point.file_path) === "python";
  const check_1 = new RegExp("@pytest.fixture*").test(
    extract_decorator_block(read_file_lines(entry_point.file_path), entry_point.start_line),
  );
  return check_0 && check_1;
}

03The --stage insertion path: five gates before any write, dry-run by default

The --stage subcommand shipped and was hardened at review. It reuses validate_registry, then adds cross-rule uniqueness checks the singleton-array validator cannot see. Each gate is a hard reject; only after all five pass does a dry-run print the entry — and only --apply writes, through atomic_update_registry with an under-lock re-check.

deliberate safety inversion — kept and documented

--stage is dry-run by default and writes only with --apply. This inverts the rest of reconcile_registry.ts, where every reconciliation signal applies by default and previews with --dry-run (passing --dry-run to --stage is itself an error). Inserting a brand-new catalog entry is the higher-stakes operation, so its default is the safe one.

Gate 4 was added at review — a function_name already claimed by another rule is rejected, keeping the barrel↔registry mapping a bijection. Gate 5 forces the human to place the .ts and rebuild core first. Below: the evidence gate that gate 1 reuses.

known_issues_registry.ts · validate_entry() — the evidence gate gate 1 reusesas shipped
// Evidence gate: a wip entry that carries an authored classifier must have
// fired in a real triage run (observed_count >= 1).
const classifier = record["classifier"] as { kind?: unknown };
if (record["status"] === "wip" && classifier.kind !== "none") {
  const observed_count = record["observed_count"];
  if (typeof observed_count !== "number" || observed_count < 1) {
    throw new RegistryValidationError(
      `${at_id}.observed_count: a wip entry with an authored classifier ` +
      `must record observed_count >= 1`,
    );
  }
}
