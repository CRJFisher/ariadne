The fix as built: a JSDoc fallback split across two helpers

extract_parameter_type keeps its structural-annotation path, then falls back to extract_jsdoc_param_type. That helper climbs the param identifier to its enclosing function-like node — re-anchoring on the const declaration for arrow/expression functions — reads the leading JSDoc via find_preceding_jsdoc, and delegates to match_jsdoc_param_type.

Before — structural child only

export function extract_parameter_type(node) {

  if (type_node) return type_node.text;

}

After — JSDoc fallback (2 helpers)

symbol_factories.javascript.ts
export function extract_parameter_type(node) {
  const type_node = node.childForFieldName("type");
  if (type_node) return type_node.text;  // structural wins
  return extract_jsdoc_param_type(node);
}
function extract_jsdoc_param_type(node) {
  if (node.parent?.type === "catch_clause") return undefined; // guard
  const fn = enclosing_function_like(node); // re-anchors on const decl
  const doc = find_preceding_jsdoc(fn);
  return doc && match_jsdoc_param_type(doc.text, node.text);
}
function match_jsdoc_param_type(doc, name) { // exact, dotted-aware
  return doc.match(new RegExp(
    `@param\\s+\\{([^}]+)\\}\\s+\\[?${esc(name)}\\b`))?.[1];
}

match_jsdoc_param_type matches by exact (possibly dotted) name and reads generics verbatim, e.g. Array<Module>; the optional [name] syntax is accepted.

Blast radius — as built

One file edited — symbol_factories.javascript.ts — adding two helpers. No data-model change (ParameterDefinition.type already existed), no resolver edit, no bindings edit, no schema bump. The structural-annotation path stays first, so existing TS-flavoured JS keeps working.

Edge cases the implementation handles

Matching purely by name is exact — but the same @definition.parameter capture also fires on a catch-clause variable, so a name collision had to be guarded.

Catch-clause collision — guarded

A catch (e) binding is captured under the same @definition.parameter name as a function parameter, so a sibling /** @param {Foo} e */ could mis-type it. extract_jsdoc_param_type returns undefined when the param node's parent is a catch_clause.
