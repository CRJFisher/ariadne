TASK-362.3 · Information architecture · Call-resolution axis

Extract hidden language logic into dotted leaves — resolve_references & references

program → TASK-362 effort M risk low–medium 6 extractions + 1 git-mv 3 languages Rust · Python · TS/JS 7 small rows ride along

Ariadne reads source files and works out which functions call which, so it can find a codebase's entry points. It supports several languages, and its cleanest habit is to keep each language's quirks in its own file, named with a dotted suffix: import_resolution.rust.ts, import_resolution.python.ts, and so on — a plain dispatcher on top hands each file to the right leaf. The import side of the code already works this way. The call-resolution side did not: six files with neutral names like function_call.ts and path_resolution.ts quietly held Rust-only or Python-only logic inside them, invisible from the outside. A newcomer adding a fifth language would have had to read every file body to find them. This work moved that hidden logic out into properly-named dotted leaves — mostly cut-and-paste with tests moved alongside, no behaviour change — so the structure finally tells the truth about what each file does.

Why two shapes, not one uniform fan

A literal switch(language) inside constructor.ts or function_call.ts would duplicate the shared resolution spine into every leaf — so the spine calls one .rust.ts leaf unconditionally and the leaf guards itself on Self / path_prefix.
