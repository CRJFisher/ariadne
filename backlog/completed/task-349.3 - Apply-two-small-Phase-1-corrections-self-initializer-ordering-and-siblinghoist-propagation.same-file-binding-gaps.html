C.1 spans the Rust indexer too

The carve-out reads VariableDefinition.initialized_from_call — a field only the JS/TS indexers emit. The serde target is Rust, so detecting the self-initializer there needs a matching extract_call_initializer_name in symbol_factories.rust.ts, wired into the Rust capture handlers for let, let mut, and const.

symbol_factories.rust.ts — extract_call_initializer_name (Rust parity for initialized_from_call)
export function extract_call_initializer_name(node): SymbolName | undefined {
  let assignment = node.type === "identifier" ? node.parent : node;
  // covers `let`, `let mut`, `const`:
  if (assignment.type !== "let_declaration" && assignment.type !== "const_item") return;

  const value = assignment.childForFieldName("value");
  if (value?.type !== "call_expression") return;

  let fn = value.childForFieldName("function");
  // turbofish `x::<T>()` wraps the callee in a generic_function:
  if (fn?.type === "generic_function") fn = fn.childForFieldName("function") ?? fn;
  return fn?.type === "identifier" ? fn.text : undefined;
}

The riskiest part: keep both corrections narrow

narrow scoping — correct shadowing elsewhere must be unchanged (AC #3)

C.1 applies only to the self-initializer case — a let x = … x(…) reference inside its own initializer; every other shadowing case must continue to resolve to the local.

C.2 propagates a function only into sibling scopes that lexically reach it, never into unrelated scopes. Over-widening either edit reintroduces wrong bindings the corpus depends on.

confinement — corrected scope (AC #4)

C.2 is confined to resolve_references/name_resolution.ts (Step 3 of resolve_scope_recursive + collect_hoisted_functions). C.1 spans two files: the carve-out in name_resolution.ts Step 2, plus the Rust indexer parity — extract_call_initializer_name in symbol_factories.rust.ts wired into the Rust capture handlers — so initialized_from_call is populated for Rust as it already is for JS/TS.

two deliberate edges — real, reviewed decisions

(a) Scope-keyed, not position-keyed. The carve-out drops the self-initializer local from the whole scope map — fine for the leaf-value self-initializers this targets (the serde case); position-aware resolution would be needed only if such a local were later a method/dispatch receiver, which is out of scope.

(b) Hoist over-approximates toward reachability. The safe direction for entry-point detection — but only for a name with no competing binding, which in valid code is never referenced from a scope that cannot reach it, so valid code is unaffected.
