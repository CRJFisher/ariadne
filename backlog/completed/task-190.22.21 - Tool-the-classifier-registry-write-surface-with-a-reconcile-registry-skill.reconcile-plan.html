Task 190.22.21: reconcile-registry — Tooling the Registry Write Surface

The classifier registry is a human-owned write surface, like backlog/. reconcile-registry is its decision skill over one fenced writer — the registry's exact analogue of prioritize over export_to_backlog.ts: a thin, human-invoked surface that detects work the rest of the pipeline has already done and proposes the mechanical flips.

Three surfaces, each with one fenced writer

The pipeline has three human-owned write surfaces. Each pairs a deliberate decision step with exactly one fenced writer; core fixes are human engineering by design.

Three mechanical writes, nothing more

The skill never authors rule prose and never makes the permanent judgment — those stay human creative work. It detects three signals, proposes the corresponding writes, shows the diff, and on confirmation writes through the one fenced writer:

#Signal (mechanically detected)Proposed registry write
1A fix-bearing git log scope (fix/feat types only) matches a wip rule's backlog_task by exact id — never prefix (190.22 ≠ 190.22.21); range scopes expand via the shared grammar in scripts/check-commit-message.tswip → fixed, citing the newest matching commit subject
2Each project's latest finalized triage_results[].classifier_regressions[] names a rule_id (which carries the registry rule's group_id)set drift_detected: true; append new drift_evidence[] rows (append-only, deduped by entry_index — re-runs are idempotent)
3Human elects to promote a rule to permanent (--id <group_id> --promote)flip the status and regenerate permanent_data.ts; the sync test guards it thereafter

Preview → narrow → apply

The workflow mirrors prioritize exactly: a --dry-run scans every signal and prints the proposed changeset writing nothing; selectors narrow the set; dropping --dry-run applies through atomic_update_registry — one lock-fenced read-mutate-write per invocation, with proposals re-folded onto the locked read so a stale preview degrades to a no-op.

Selectors (mirroring prioritize)

FlagEffect
--dry-runScan every signal and print the proposed changeset, grouped by transition; writes nothing. Always the first run.

Same shape as prioritize, deliberately. The skill owns no logic of its own, drives a single script, and is disable-model-invocation: true — only a human can trigger it; the model never self-invokes. The scripts live under .claude/skills/triage/scripts/ because that is where the registry and its loaders already live, exactly as prioritize points at a script under plan/scripts/.

Which lifecycle arrows carry a detector

The lifecycle diagram shows every transition as a human edit, and that holds — the human remains the decider on every arrow. Two arrows carry a detector (the signal is found mechanically and proposed) and one carries a mechanical apply-step (the regeneration the lifecycle doc describes):

Two structural guards

Cheap writes alone don't keep the surface honest. Two whole-repo invariant guards enforce it, paralleling the AST write-boundary test:

permanent_data.sync.test.ts

Asserts the committed permanent_data.ts byte-equals the slice freshly rendered from the source registry, through the shared render_permanent_slice_module in @ariadnejs/types — the same function the generator writes through. The bundled core slice cannot silently drift from the registry: a hand-edit to either file fails CI. The "AUTO-GENERATED" header has teeth.

registry_writers.test.ts

The AST walk in packages/skill-fs/src/registry_writers.test.ts flags any raw write primitive against a registry-shaped path and any serializer call outside an allowlisted file. reconcile_registry.ts reaches the registry only via atomic_update_registry; it is the one entry in ALLOWED_SERIALIZER_CALLERS, and its only serializer call sits inside the mutator closure.

The script's only stdout is one JSON summary:

Promotion is guarded; the human stays the decider. A rule whose classifier.kind is "none" is refused — core's validate_permanent_slice cannot load an unclassified permanent rule, so the slice generator filters on status === "permanent" and classifier.kind !== "none". wip → fixed scans this repo's git log — Ariadne defects are fixed here. No KnownIssue field changes, so the registry stays schema_version: 1. The skill proposes; the human confirms every flip.
