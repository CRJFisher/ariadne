The prefix is type-last — the qualifier is the segment before the type

A constructor's path_prefix keeps the full type path: the final segment is the type (carried also as name), and the type's immediate module qualifier is the second-to-last segment — that single qualifier is resolved in scope, not every leading segment.

// the branch — type-last prefix, immediate-module qualifier only:
  const prefix = normalize_path_prefix(call_ref.path_prefix ?? []);  // drop crate/self/super
  if (prefix.length < 2) return null;              // need [module, Type]
  const type_name = call_ref.name;                  // last segment = the type
  const qualifier = prefix[prefix.length - 2];      // segment BEFORE the type
  const qualifier_id = resolutions.resolve(call_ref.scope_id, qualifier);
  if (!qualifier_id) return null;              // qualifier not in scope → bail
  if (definitions.get(qualifier_id)?.kind !== "namespace") return null; // must be a Rust `mod`
  return resolve_in_module_body(qualifier, ...defining_scope_id, type_name, scopes, definitions);

A lone leading crate / self / super is stripped by normalize_path_prefix so the path does not die on a literal anchor segment; the qualifier must then resolve to a mod (namespace) in scope or the branch returns null.

Disambiguation — the lookup is scoped to one module's body, never a global scan

Two in-scope modules each exposing a Driver resolve to the correct one because the type is looked up in the specific module body its qualifier names — alpha for one call, beta for the other — never a collapsed global name map.

alpha qualifier → alpha's Driver beta qualifier → beta's Driver fixture: ambiguous_path_constructor.rs
why a module-scoped lookup is the guard

The type binds through the module's scope definitions, not its file-level exports — so the alpha/beta structs need not be pub, and each call's qualifier names one specific mod body, never a collapsed global name map.
