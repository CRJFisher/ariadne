01The link that stalled, and the bridge that closed it

BEFORE: prioritize held only member_symbol + run_id, but get_entry_context.ts accepted only the run-local entry_index — the flow stalled at the first hop. AS-BUILT: the script gained the four-field selector and resolves the entry itself.

What closed the link

Prioritize holds (project, run_id, member_symbol) per evidence row and never an entry_index; the script accepts the identity directly and does the last-mile lookup itself.

The --entry selector stays for the triage-investigator caller — each dispatches the key it naturally holds, so both are load-bearing, not a compatibility layer.

02Why the two keys meet — a direct field match

The four stable fields are already present in each TriageEntry, so resolving member_symbol → entry is a direct .filter() field match — no new data, no new store, one relativize on the path.

03The chosen design — the stable selector, four discrete flags

Two fixes were on the table; the one that landed keeps the drift-unstable index out of prioritize entirely, and its CLI encoding is now settled: four discrete flags plus a required run.

1 OPTION 1 built

Extend get_entry_context.ts with a stable selector

--file --name --kind --line plus a mandatory --run-id; the script resolves member_symbol → entry internally against that run's triage state. Prioritize keeps the stable identity and never touches the unstable index. The drift-fragile translation lives in exactly one place, right next to the state file it reads.

2 OPTION 2 rejected

Thread entry_index through prioritize

Pair each plan group back to its source NovelIssue per run_id at dispatch time to recover the index. Re-introduces the exact index the plan engine deliberately dropped for being line-drift unstable — prioritize would own a fragile positional key across sweep boundaries.

CLI encoding · DECIDED

The selector is four discrete flags — --file <path> --name <name> --kind <kind> --line <n> — no JSON quoting to serialize or escape. --run-id is REQUIRED in member-symbol mode: start_line is run-specific, so the LATEST-run fallback would resolve against the wrong run.

The parser rejects mixing --entry with the member flags, a partial flag set, and member mode without a run.

landed in: get_entry_context.ts · parse_entry_selector

04The resolution mechanism, as built — three pure functions

Parsing, matching, and failure diagnostics are pure exported functions with exact-string tests; the CLI wrapper only wires argv and exit codes.

The normalization contract · single-sourced

relativize lives once in src/store/paths.ts, shared by three call sites: the publish side (finalize/output.ts), the TP cache (finalize/confirmed_unreachable_reuse.ts), and this lookup.

Published member symbols carry project-relative paths while state entries may hold absolute ones — so the match key cannot drift.

Review found the publish side previously carried a private identical copy; it is now one function.

load-bearing: relativize(file_path, project_path) in src/store/paths.ts
