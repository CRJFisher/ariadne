TASK-362.1 · Information architecture · Language axis

Unify language identity: one detect_language, one parse-dispatch point

program → TASK-362 effort M risk low 1 detect_language at ingress 3 dropped threads re-attached 16 builtins read a param

Before Ariadne can index a file it must know one thing: what programming language is this? That question has a correct answer exactly once — the moment a file enters the system — and the front half of the pipeline already computes it there and carries it forward as an explicit value: on the parsed file, on its semantic index, and in a languages map handed to every resolution phase. But three places downstream threw that answer away and re-derived it from the file's path string, and the three re-derivations disagree — one returns nothing on an unknown extension, one throws, and one silently guesses "TypeScript", mislabelling files during the call-graph trace. This task re-attaches the dropped thread: language is passed as a parameter into trace_call_graph, the classifier builtins, and the diagnostics extractor, so none of them guess. Path-based detection survives only at the true ingress points, behind one canonical detect_language.

packages/core/src/detect_language.tsnew · canonical
// The single path-based language detector. Callers are
// ingress-only: parse_file.ts, file-discovery filtering,
// and skill-side loaders re-entering persisted JSON.
export function detect_language(file_path: string): Language | null {
  if (file_path.endsWith(".ts") || file_path.endsWith(".tsx")) {
    return "typescript";
  }
  if (
    file_path.endsWith(".js") ||
    file_path.endsWith(".jsx") ||
    file_path.endsWith(".mjs") ||
    file_path.endsWith(".cjs")
  ) {
    return "javascript";
  }
  if (file_path.endsWith(".py")) return "python";
  if (file_path.endsWith(".rs")) return "rust";
  // go / java / cpp recognized, not yet supported
  return null;
}

export function assert_language(file_path: string): Language {
  const language = detect_language(file_path);
  if (language === null) {
    const ext = file_path.split(".").pop()?.toLowerCase();
    throw new Error(`Unsupported file extension: ${ext}`);
  }
  return language;
}

// The single parse-phase dispatch point; consumes
// assert_language and builds parsers from the parsers.ts
// registry — the four grammar imports live at one site.
import Parser from "tree-sitter";
import { assert_language } from "../detect_language";
import { LANGUAGE_TO_TREESITTER_LANG } from "../index_single_file/query_code_tree/parsers";

function get_parser(language: Language): Parser {
  const grammar = LANGUAGE_TO_TREESITTER_LANG.get(language);
  if (!grammar) throw new Error(`Unsupported language: ${language}`);
  const parser = new Parser();
  parser.setLanguage(grammar);
  return parser;
}

export function parse_file(file_path: FilePath, content: string, buffer_size: number): ParsedFile {
  const language = assert_language(file_path); // fails loud on unknown
  const parser = get_parser(language);
  const tree = parser.parse(content, undefined, { bufferSize: buffer_size });
  return { file_path, tree, lang: language, /* …line metadata */ };
}

Support — where failing loud actually lives

trace_call_graph stops re-deriving and reads the thread

The one behavior change — read, don't re-derive

trace_call_graph no longer detects language — it reads the languages parameter it is handed. By construction the lookup does not miss: every definition came from an already-parsed file, so the old TypeScript default never arises downstream.

Two sites fail loud instead of guessing: assert_language throws at ingress on an unsupported extension, and a missed downstream lookup makes trace_call_graph throw No language recorded for <path> rather than defaulting.

A formerly-silent mislabel becomes a loud crash — and nothing is left behind: no re-exports, no aliases, no transitional layer.
