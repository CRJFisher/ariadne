Where Ariadne’s structure diverges from its purpose

packages/core · types · mcp · skill-fs · skill-protocol verified against source 3-stage intention tree

Ariadne reads a codebase and works out which functions call which — a call graph — so it can find the program’s real entry points. Its folders mirror that job in three stages: index each file, resolve the references between files, then trace the call graph. This review asks a blunt question of every file and folder: does its name tell a maintainer chasing a bug exactly where to look? The good news first — the three-stage skeleton is faithful; the folders route correctly. The trouble sits one level down. A handful of files quietly grew into “hubs” that do three jobs at once; four files ballooned past 800 lines under a name that covers only their first job; and language-specific logic (the Python rule, the Rust rule) hides inside neutrally-named bodies instead of the repo’s own dotted feature.language.ts convention. This page maps those divergences onto the pipeline to make them visible.

The trunk is sound; every defect this page shows sits one level inside these boxes. The three core stages carry the work — shared types and the periphery are correct as they stand.

Latent bug

An unknown extension reaching the trace stage is silently analyzed as TypeScript — no error, no null, no signal. Add a fifth language and forget this one copy, and its files are mislabeled without a trace.

The canonical copy is a coupling magnet: 14 check_*.ts builtins import detect_language from the 867-LOC classification megafile, giving every pipeline-support check a hard import edge into a product megafile for one utility.

Where the language axis is correctly held out

Healthy negative space

Language-specificity is properly confined to the extraction and resolution stages. The support tissue — persistence/, logging/, profiling/, introspection/ — and the periphery — skill-fs, skill-protocol — carry zero language-specific code, exactly as they should.

The skill-protocol wire schema is the deliberate neutral seam: kind: function | method | constructor, with no language discriminator. The language axis is held out of the pipeline by construction, so the periphery stays zero-cost when a fifth language arrives.
