Self-Healing Pipeline · Multi-Lens Review

A strong core whose loudest safety promises have the weakest enforcement

4 skills → 1 loop 166 findings 7 root-cause themes 1 CRITICAL

The self-healing pipeline is a loop that turns Ariadne's own call-graph blind spots into fixed code: four skills hand work down a chain — triage investigates dead-looking entry points, plan sweeps false positives into planned work, prioritize funds and exports that work into the backlog, and reconcile-registry is the human-owned keeper of the "permanently unknowable" list. Two of those surfaces are meant to be human-only. This page is a completed review of that loop, not a change to it. Its verdict is one sentence: the core is well built, but the safety promises the docs make most loudly are the ones with the least real enforcement behind them. Below, the strong parts sit next to the hollow spots so the gap is something you see rather than read — sharpest where one human-owned surface is guarded three ways and the other is guarded only by a sentence.

The asymmetry

Structurally enforced

keep — affirmed by multiple lenses (§1:13)

  • Pass-by-reference hand-offs at every wave boundary; terse or empty text returns
  • File-authoritative verdicts — "Ignore its <result> body entirely"
  • Single-producer artifacts and append-only run stores
  • Deterministic-first ordering — registry builtins classify before any LLM dispatch
  • Fail-closed export adapter — refuses to write without --assignments
  • Registry write path is triple-enforced — lock sidecar + AST-walk test + PreToolUse guard
  • The finalize guard: a half-finished sweep can only block retirement, never spuriously resolve

Advertised but hollow

the loudly-promised safety, weakly enforced (§1:16–22)

  • "Only writer of backlog/" is prose-only and already false — no hook, no test, no allowlist
  • Judge outputs gate irreversible decisions with shape-only checks — consolidation.json is ungated
  • Doc-vs-code drift on the write-boundary contracts a human relies on
  • Crash-recovery and write-atomicity discipline applied only to the registry
  • dedup_key is the least drift-stable identity — any commit resurfaces funded work as fresh proposals

Paired anchor: registry vs backlog — the same kind of human-owned surface, opposite enforcement.
